重新创建存储客户端后相同消息没有再次 PUT。第五轮修改历史时产生新内容，
此前 trace 仍能恢复旧值。真实不可达地址导致内联回退；不存在的媒体 ID
通过真实媒体 API 返回错误并触发 RestoreError。没有删除任何附件来制造故障。

请求数包含重复的完整性验证和下载，不能直接当作生产每轮请求开销。
第一轮编码约 4.15 秒，后五轮约 74–170 毫秒，是本机合成负载测量，不是性能承诺。

**不是总磁盘/费用基准**：没有比较 ClickHouse 压缩后的磁盘占用，也没有把
Postgres 索引/WAL、对象请求计费、备份、保留期和孤立附件回收计入。因此不能
声称总存储成本降低 66.65%。

## 过程中修正的问题

- 测试主机遇到 Windows Docker 旧 socket 启动故障，恢复本地环境后才开始真实验证。
- 第一次端到端脚本失败：v2 observations 默认字段不含 input/output。
  修正为显式 `fields=core,basic,io` 后真实读回成功。失败测试生成的合成数据保留。
- 独立审查发现 deepcopy 会保留共享对象身份，导致未选字段也被替换；现改为
  独立 JSON 容器复制，并通过序列化往返回归测试。
- Unicode 孤立代理字符改为转义保存；编解码会改变值的字面代理对保持内联。
